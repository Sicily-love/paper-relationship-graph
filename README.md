# Paper Atlas

Paper Atlas 是一个面向本地论文库的整理与浏览工具。它把论文按类别和年份排入时间泳道，显示库内引用关系，并集中处理 arXiv、领域高被引和共同引用推荐。

![Paper Atlas v1.3.0 时间泳道界面](preview.png)

当前版本为 [v1.3.0](https://github.com/Sicily-love/paper-relationship-graph/releases/tag/v1.3.0)。App 侧栏底部的版本号可以打开历次更新记录。

> Release 目前只提供 GitHub 自动生成的源码归档，没有可直接安装的 DMG。仓库中的 `Paper Atlas.app` 和 `dist/` 均为本机构建产物，不会提交到 Git。

## 主要功能

- 用时间泳道展示论文的分类、年份和库内引用关系。
- 单击论文查看一阶引用，双击打开摘要、元数据和引用详情。
- 按搜索主题获取最新 arXiv 与 OpenAlex 高被引论文。
- 根据多篇库内论文的共同参考文献生成推荐候选。
- 从本地 PDF 参考文献段维护库外引用索引，并显示可解释的推荐分。
- 每次搜索前根据当前分类论文更新动态关键词和代表论文参考。
- 审核候选、下载 PDF、归档到确认后的类别并重建图谱。
- 在 App 中确认自动分类无法判定的待审核论文。
- 在 macOS 上使用 `launchd` 执行每日分类和论文发现。
- 检查论文库状态，备份搜索主题、候选、审核记录和任务配置。
- 运行固定质量评测和系统诊断，复制报告用于排查发现与自动任务问题。

## 快速开始

### 从源码运行

需要 Python 3.10 或更高版本。论文库位于仓库上一级目录时，运行：

```bash
make start
```

论文库在其他位置时，明确指定路径：

```bash
python3 scripts/start_app.py --papers-dir "/path/to/paper-library"
```

首次启动会在项目目录创建 `.venv` 并联网安装 PDF 读取依赖。程序随后启动一个只监听 `127.0.0.1` 的本地服务，并打开系统默认浏览器；关闭终端后服务随之停止。不要直接打开 `web/index.html`，否则论文发现、归档和任务管理不可用。

Windows 可以双击 `platform/windows/start-paper-atlas.bat`。该脚本默认把仓库的上一级目录作为论文库。

### 构建 macOS App

构建需要 Xcode Command Line Tools。首次构建还需要联网下载并校验 Python.org 通用架构运行时：

```bash
make mac-app
open "Paper Atlas.app"
```

App 内置 Intel 与 Apple Silicon 通用架构 Python，以及 PDF 读取组件。它使用 WebKit 直接显示界面，不启动 localhost 服务，也不依赖默认浏览器或常驻终端。

首次打开时请选择论文库根目录。当前版本没有新建空论文库向导；所选目录应已包含下列分类目录，并至少有一篇已分类 PDF。启用每日任务前，建议先把 App 移到 `/Applications` 等固定位置。

本机构建默认使用临时签名，macOS 可能阻止直接打开。可以在 Finder 中右键 App，选择“打开”。这不等同于 Developer ID 签名或 Apple 公证。

## 论文库结构

Paper Atlas 使用固定的十类目录。每篇论文应直接放在对应类别下：

```text
paper-library/
├── 01_模型架构与训练优化/
├── 02_注意力机制与长上下文/
├── 03_MoE与稀疏模型/
├── 04_量化与低精度计算/
├── 05_分布式训练与数据基础设施/
├── 06_GPU内核_编译器与性能工程/
├── 07_GPU内核智能体与自动调优/
├── 08_通用智能体与自主学习/
├── 09_生成模型与视频系统/
└── 10_大模型技术报告与推理训练/
```

PDF 文件名作为论文标题。年份、作者和摘要从 PDF 中尝试提取；扫描件、排版特殊或元数据缺失的文件可能无法完整识别。内容哈希相同的 PDF 会被标记为重复文件。

PPTX 会进入分类与健康检查，但当前不会生成图谱节点、摘要或引用关系。

## 使用方式

### 浏览图谱

横向位置表示年份，纵向泳道表示类别。节点大小按库内被引用次数缩放，并设有上下限；每个类别中库内被引最多的论文显示为主节点。

单击节点后，橙色表示“本文引用”，蓝色表示“引用本文”；双击节点打开论文详情。引用关系来自本地 PDF 参考文献中的标题匹配，并附带匹配可信度和证据。它适合浏览库内关系，不应视为完整或权威的引文数据库。

### 发现和归档论文

候选有三种来源：

- 最新 arXiv：按启用的搜索主题获取近期论文，并过滤低相关结果。
- 领域高被引：把主题关键词、当前类别的动态术语和代表论文作为软描述，通过 OpenAlex 语义搜索召回含义相近的论文，再按可调引用量下限筛选和排序。
- 共同引用：本地图谱和 PDF 参考文献索引负责汇总引用证据，OpenAlex 负责解析并补充库外候选；共同引用次数下限可以调整。

“保存并立即发现”会同时运行 arXiv 和领域高被引搜索。共同引用需要在“发现论文”菜单中单独运行。三个来源会合并去重，论文库中已有的同标题论文不会再次进入候选；结果提示会单独列出已在库中和低于 OpenAlex 阈值的命中。

候选会得到一个可修改的建议类别和综合推荐分。评分综合主题相关度、共同引用、按年份校正的引用量、来源互证与类别缺口，但列表仍按时间从新到旧排列。候选可以暂时移出、永久忽略、清除引用证据，或替换库内旧版本；“加入论文库”会下载并验证 PDF、检查重复内容、记录审核决定并尝试重建图谱。若图谱重建失败，PDF 和审核记录仍会保留，状态标记为待重试。

### 每日任务

macOS App 可以安装两项本机任务：

| 默认时间 | 任务 | 行为 |
| --- | --- | --- |
| 10:30 | 论文分类整理 | 只移动高置信度结果，其余文件保留待确认 |
| 11:00 | 每日论文发现 | 获取最新 arXiv、领域高被引与共同引用候选 |

修改开关或时间后，必须点击“保存并启用”才会更新 `launchd` 配置。App 关闭后任务仍可按时运行。Windows、Linux 和源码浏览器模式不会自动安装定时任务。

无法高置信度归类的文件会进入“运行与数据”中的“分类待审核”。确认类别后，App 会移动文件、重建图谱并刷新已打开的页面。

App 使用进程锁保证同一任务只运行一个实例；重复触发会记录为已跳过。仍建议只保留 App 的一套 `launchd` 调度。

### 检查和备份

“运行与数据”会检查分类目录、PDF 与图谱节点、引用边、候选数据以及待重建状态。“运行诊断”还会执行固定发现评测，检查缓存、外部数据服务和每日任务，并生成可复制报告。导出的备份包含搜索主题、候选、审核记录和任务配置，不包含论文 PDF，也不复制图谱文件。恢复备份后，需要再次点击“保存并启用”才能把任务时间写入 `launchd`。

同一页面的“发现调试日志”记录动态主题画像、接口重试、每个主题的召回与阈值过滤数量、库内去重和错误信息。日志保存在运行目录的 `.cache/discovery-debug.jsonl`，达到 5 MB 后自动轮换。

## 数据与隐私

论文整理、图谱浏览和已下载 PDF 解析都在本机完成。Paper Atlas 没有账户、遥测或云同步。

以下操作需要联网：

- 搜索关键词会发送给 arXiv 和 OpenAlex；
- 论文标题会发送给 OpenAlex，用于引用匹配和共同引用计算；
- 接受候选时会从候选提供的 PDF 地址下载文件。

原生 App 的可变数据保存在：

```text
~/Library/Application Support/Paper Atlas/runtime
```

论文 PDF 始终保存在所选论文库中。源码模式使用仓库中的 `config/`、`web/data/` 和 `.cache/`，与原生 App 的状态互不共享。因此，在仓库中运行 `make update` 不会更新已安装 App 的图谱。

构建 App 时会清空包内的自定义搜索主题、候选和审核记录，并检查用户绝对路径。仓库仍跟踪 `web/data/graph*` 和候选数据快照；如果用自己的论文库重建这些文件，请在推送前检查其中的论文标题和元数据是否适合公开。

## 已知限制

- 只支持当前固定的十类目录，没有图形化的分类体系编辑器。
- 引用关系和库外参考文献索引依赖 PDF 文本提取与标题识别，可能漏检或误判。
- 扫描版 PDF 的年份、作者、摘要和参考文献通常无法可靠提取。
- 当前 Release 没有经过 Developer ID 签名和 Apple 公证的安装包。
- macOS App 尚不能创建空论文库。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `make start` | 启动源码浏览器版本 |
| `make classify` | 保守分类新增论文并重建图谱 |
| `make update` | 检查分类并重建图谱 |
| `make health` | 检查论文库和生成数据 |
| `make discover` | 搜索最新 arXiv 与领域高被引论文 |
| `make discover-shared` | 生成共同引用候选 |
| `make test` | 运行自动测试 |
| `make release-notes` | 从 `CHANGELOG.md` 生成 App 内更新记录 |
| `make mac-app` | 构建内置 Python 的通用架构 macOS App |
| `make release` | 生成本地测试 DMG 和 SHA-256 文件 |
| `make release-check` | 检查版本、运行资源、签名和数据一致性 |

前端不需要 npm 构建。修改 `web/` 后刷新页面即可；修改 `CHANGELOG.md` 或 `VERSION` 后，应运行 `make release-notes`。

## 发布说明

`make release` 生成临时签名的本地测试 DMG，并附带 SHA-256 校验文件。SHA-256 只能用于核对文件是否发生变化，不能证明发布者身份；临时签名和未经公证的 DMG 不应作为公开安装包分发。

公开发布必须使用 Developer ID Application 证书并完成 Apple 公证：

```bash
PAPER_ATLAS_SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" \
PAPER_ATLAS_NOTARY_PROFILE="paper-atlas-notary" \
make release-public
```

`PAPER_ATLAS_NOTARY_PROFILE` 需要事先通过 `xcrun notarytool store-credentials` 保存。缺少证书、公证配置或公证票据时，`make release-public` 会直接失败。

GitHub Actions 会在 Linux 上运行测试，并在 macOS 上验证 App 和 DMG 能否构建，但不会上传临时签名产物。版本变化见 [CHANGELOG.md](CHANGELOG.md)。

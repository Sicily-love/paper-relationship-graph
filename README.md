# Paper Relationship Graph

从本地分类论文库生成可交互的球状关系图。项目不上传或复制 PDF，只把标题、年份、类别和论文库内部关系写入静态数据文件。

## 零构建启动

日常使用不需要执行构建命令，也不需要 Node.js、npm 或前端编译：

- macOS 推荐：双击 `Paper Atlas.app`，关系图谱直接显示在应用窗口中，不打开浏览器，也不监听 `127.0.0.1` 本地端口
- macOS 备用：双击 `platform/macos/启动 Paper Atlas.command`
- Windows：双击 `platform/windows/start-paper-atlas.bat`
- 命令行：运行 `make start`

首次双击 macOS 应用时，请在系统窗口中选择包含分类文件夹与本项目的 `paper` 文件夹，用于授予“下载”目录访问权限。随后应用会自动创建本地 Python 环境并安装 PDF 读取组件，之后直接打开页面。启动器会检测论文文件是否比现有星图更新；需要时自动刷新图谱。通过页面加入候选论文后，也会自动归档并更新图谱。

如需开机自动运行，可在 macOS“系统设置 → 通用 → 登录项”中添加 `Paper Atlas.app`。

## 项目结构

- `Paper Atlas.app`：macOS 日常启动入口
- `web/`：无需前端构建即可打开的图谱页面和数据
- `scripts/`：本地服务、论文发现、分类更新与数据维护程序
- `config/`：发现主题等可调整配置
- `platform/`：各系统的备用启动器和 macOS 原生应用源码
- `tests/`：自动校验

日常使用无需重新生成应用。修改 macOS 原生启动器后，维护者可运行 `make mac-app` 更新 `Paper Atlas.app`。

## 图谱规则

- 一个节点代表一篇唯一论文；SHA-256 完全相同的 PDF 会合并。
- 每个类别选择一个主节点：在当前论文库中被其他论文引用次数最多的论文。
- 节点大小表示库内被引用次数，并使用固定的最小、最大半径防止极端尺寸。
- 引用边方向为 `引用论文 -> 被引用论文`。
- 时间不使用连线：年份决定三维球壳半径，较早论文靠近球心，较新论文靠近外层；二维投影不要求严格保持远近顺序。
- 不生成内容相似边，避免与类别关系重复。
- 点击论文会将球体旋转到该论文位于中心的位置，并聚焦一阶关系。
- 点击节点后，浮动信息框显示作者、摘要、年份、类别，以及库内引用和被引用论文；关系列表中的论文可以继续点击跳转。
- 通过本地服务打开时，可以从浮动信息框直接打开论文库中的 PDF；PDF 不会被复制进仓库。
- 从类别下拉框选择类别后，会高亮该类别并将类别主节点旋转到中心。
- 顶部搜索会同时筛选图谱论文和发现候选，并在星图中高亮匹配节点。

## 论文发现与推荐

发现流程包含两个互补来源，并且默认只生成候选，不会自动下载、移动或删除论文：

- **共同引用推荐**：先将库内论文映射到 OpenAlex，再聚合它们的外部参考文献。只有被至少 2 篇库内论文共同引用、且尚未存在于论文库的论文才会进入候选队列。
- **arXiv 主题检索**：调用 arXiv 官方 Atom API，按提交时间倒序检索最近 14 天内的论文。默认主题是“GPU 内核与编译器优化”。
- **候选自动分类**：发现完成后，根据标题、摘要、搜索主题和库内共同引用论文，为每篇候选推荐唯一主类别并预选归档下拉框；低置信度结果会标记为需确认。
- **卡片内摘要**：候选卡片可以直接展开摘要；共同引用候选会优先从 OpenAlex 公开元数据补全摘要。
- **审核记忆**：已忽略的候选不会在下一次发现时重新出现；已加入的候选会记录本地归档位置。
- **可信度与校验**：候选会检查标题、作者、年份、来源页、PDF、arXiv 编号和共同引用支撑；年份冲突或关键字段缺失会明确标记为“需核验”。

两条发现流程分别运行：

```bash
make discover         # 仅搜索 arXiv
make discover-shared  # 仅计算共同引用
```

结果写入：

- `web/data/discovery.json`：候选、推荐理由、共同引用支撑论文和审核状态
- `web/data/discovery-data.js`：供本地页面直接读取的数据
- `.cache/openalex-library.json`：库内论文的 OpenAlex 映射缓存（不提交 Git）

启动应用后，可以点击“搜索主题”直接增加、停用或删除主题，并维护关键词、排除词与每日数量。“搜索 arXiv”只刷新主题搜索结果；“共同引用”单独计算库内共同引用，并可直接设置 2–20 次的下限；“清空候选”只移除待审核候选，不删除已归档论文和审核记录。未处理候选默认保留 60 天，避免论文离开“最近 14 天”窗口后从审核队列立即消失。

### 审核后加入论文库

推荐卡片可直接选择标准类别并点击“加入论文库”，本地服务会验证下载文件、检查完全重复、归档并重建图谱；点击“忽略”会从待审核列表移除候选。命令行也可以执行相同操作：

```bash
make accept ID="arxiv:2608.12345" CATEGORY="06_GPU内核_编译器与性能工程"
```

该命令会验证下载结果是可读 PDF、检查完全重复文件、保存到指定类别，并重建分类校验与关系图谱。若不再关注某个候选：

```bash
make reject ID="openalex:W123456789"
```

论文仍严格使用一个主类别。页面会根据共同引用论文给出类别预选，但最终归档类别由用户确认；系统不会删除疑似重复论文。

## 手动生成（可选）

需要 Python 3.10+。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
make build PAPERS_DIR=..
```

生成结果：

- `web/data/graph.json`：可复用的结构化数据
- `web/data/graph-data.js`：浏览器直接加载的数据

### 新增论文后的完整更新

论文完成分类后，运行：

```bash
make update PAPERS_DIR=..
```

该命令会检查所有 PDF/PPTX 是否位于 10 个标准类别中，识别新增和移除文件，重新提取年份、作者、摘要和内部引用，重选类别主节点，并更新图数据与 `preview.png`。如果还有论文散落在根目录或未知文件夹，命令会列出文件并停止，避免图谱悄悄漏掉论文。

`preview.png` 使用本机 Chrome/Chromium 生成；未安装浏览器时，数据仍可通过 `make build` 单独生成。

### 本地查看与打开 PDF

直接打开 `web/index.html` 可以只读查看图谱。日常使用建议直接运行零构建启动器；也可以手动启动本地服务：

```bash
make serve
```

然后访问 <http://localhost:8000>。

本地服务仅监听 `127.0.0.1`；PDF 路由只能读取指定论文目录中的 PDF，管理接口也仅接受来自本机页面的请求。

## 使用其他论文目录

论文目录需要按 `数字_类别名/*.pdf` 组织：

```bash
python scripts/build_graph.py \
  --papers-dir /path/to/paper-library \
  --output-json web/data/graph.json \
  --output-js web/data/graph-data.js
```

## 校验

```bash
make test
```

当前库内引用关系通过本地 PDF 参考文献标题匹配得到；外部共同引用候选通过 OpenAlex 聚合。候选仍需人工核对来源页与 PDF 后再加入论文库。

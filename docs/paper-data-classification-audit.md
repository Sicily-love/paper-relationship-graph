# 论文数据与分类逻辑只读审计

审计日期：2026-08-28

本报告由独立 agent 基于当前仓库源码、图谱快照、候选数据和测试文件完成。审计过程未修改论文库、配置、缓存或代码。

## 结论

当前系统适合继续优化。类别用于浏览与搜索，不存在唯一标准答案，因此不建立逐篇人工金标准；规则优化以类别边界合理、相邻版本稳定、明显误分可复查为目标。数据完整性与搜索召回比追求分类准确率更重要。

## 数据质量

- 当前图谱包含 79 篇唯一论文、11 个类别、251 条库内引用边和 2,249 条外部引用记录；SHA-256 重复文件数为 0。
- 另有 1 个 `03_注意力机制与长上下文/ultraattn.pptx`。现有图谱构建器只扫描 PDF，因此 PPTX 不会成为图谱节点。
- 5 篇论文缺少作者：`p00`、`p15`、`p56`、`p62`、`p78`。
- 6 篇论文缺少摘要：`p06`、`p08`、`p45`、`p57`、`p74`、`p75`。
- 年份提取优先使用 arXiv 编号年份，可能与会议或期刊正式发表年份不同。图谱目前使用单一 `year` 字段，无法区分预印本年份与正式发表年份。

证据：`web/data/graph.json` 的 `metadata` 与 `nodes`；`scripts/build_graph.py:166-212,235-285`。

## 分类逻辑

- 11 个目录、标签和 topic 映射在表面上是一致的，但配置文件与 11 类 taxonomy 不是同一份来源，存在漂移风险。
- 使用当前分类器重算现有论文时，约 52 篇保持原类别，27 篇发生变化；置信度大致为高 40、中 20、需确认 19。
- 通用词 `attention`、`agent`、`optimization` 在跨领域论文中权重偏高，容易覆盖更具体的研究主题。
- 典型边界包括：基础 Transformer 与具体注意力优化、MoE 与泛稀疏模型、GPU 性能工程与 GPU 内核智能体、视频生成与通用扩散模型。

证据：`scripts/discover_papers.py:70-188,322-407`；`scripts/classify_library.py:63-130`。

## 引用与推荐

- 251 条库内引用边中，248 条为完整标题匹配，3 条为标题片段匹配。
- 引用方向规则能够生成 `citing_paper -> cited_paper`，但边上尚未完整保存 DOI、arXiv ID 等可追溯证据。
- 共同引用和领域高被引已使用混合召回，但最终类别仍依赖同一套词典评分，跨领域候选可能被归入错误类别。

## 已落地的第一轮修正

- 新增分类规则版本 `2026-08-28.1`，分类结果会携带规则版本，便于追踪历史结果。
- 泛化的 `attention` 不再自动压过基础架构；`Attention Is All You Need` 优先归入模型架构类别。
- 只有出现长上下文、KV cache、FlashAttention、PagedAttention 等具体信号时，才提升注意力类别。
- 保留“注意力专用量化”边界；普通量化论文不再因泛 attention 词汇失去量化类别竞争力。
- 新增基础注意力论文和现有量化边界的回归测试。
- 使用修正规则重放当前 79 篇图谱论文，结果与现有目录一致，没有触发文件移动。

## 产品决策

- 不建设逐篇人工确认的分类基准集，也不把类别准确率作为发布门槛。
- 保留少量典型边界回归样本，防止明显误分和规则漂移。
- 搜索主题允许人工选择库内参考论文；未选择时，自动使用对应类别的主节点和高被引论文。

## 后续优先级

1. 增加摘要、作者和年份字段完整性检查，并将低质量记录放入待修复队列。

3. 保持分类重放稳定，并为待确认结果提供人工调整入口。

### P1

3. 明确 GPU 智能体、GPU 性能、MoE、视频生成和大模型报告之间的优先级与负向特征。

### P2

1. 定期刷新 OpenAlex 元数据并记录来源时间。
2. 保存人工修正记录和分类器版本，支持回滚与规则漂移对比。
3. 在每次分类任务后自动生成质量摘要，而不是只报告任务是否成功。
